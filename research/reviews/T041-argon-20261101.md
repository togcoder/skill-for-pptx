# T041 [xlsx] — Argon review, 2026-11-01

**Reviewer:** Gemini 4 Argon (via `ask_argon`), different model family from the
author (OpenCode/DeepSeek).
**Scope:** T041 REPORT, `domains/xlsx/DOMAIN.md`, `chart_forge.py`,
`chart_patch.py`, `chart_audit.py` (attached files). Argon did **not** run the
repository or the tests; the review is a code/report critique, not a
reproduction. That limitation is recorded here.

**Verdict: `revise`** — fix R4–R6, R8 before acceptance.

## Findings

### R4 — blocking — combo chart series and axis mapping
`_find_chart_group` returned only the first chart group, so
`chart_patch` series patches skipped the line series of a combo, and
`chart_info inspect` omitted it. `chart_audit` compared an axis maximum against
all series, mixing left/right axes (the fixture hid this by using the same
0–240 scale on both axes).

**Fix asked:** flatten `c:ser` across all groups; attach each series to its
`c:axId`; check max against that axis's series only.

### R5 — major — OOXML child order
`manualLayout` was written as `xMode, x, yMode, y, …` instead of
`xMode, yMode, wMode, hMode, x, y, w, h`. `a:solidFill` could be appended after
`a:prstDash` in `a:ln`. Both can make Excel ignore the property or offer repair.

**Fix asked:** emit the schema order; insert fill before dash/join/end-cap.

### R6 — major — print area and cache checks were stubs
`inside_print_area` was set to `True` whenever a print area existed, without
comparing coordinates. The cache check looked at the first point only, and
xlsxwriter may omit `c:numCache`, so pie/density/axis checks could silently
skip.

**Fix asked:** compare the chart rect to the print-area rect; compare every
cache point; fall back to worksheet values when the cache is absent.

### R7 — minor — rung 4–5 was a manual run; “full control” overclaims
The chart export was a separate COM command; `--render` used GridCraft only.
The title promised every chart property while ChartEx types, error bars and
theme-colour resolution are missing.

**Fix asked:** put Excel export in `--render`; narrow the claim to the supported
standard DrawingML types and list ChartEx as raw recipes.

### R8 — minor — hard-coded ArtCraft path / overlap
`chart_forge._render_gridcraft` hard-coded `D:\artcraft\GridCraft\gridcraft-cli.exe`
instead of using `gridcraft_bridge`. The bridge vs builder boundary was open.

**Fix asked:** use the bridge; define the adapter vs native OOXML builder
boundary.

### R9 — minor — limitations incomplete
Missing: one-cell anchor position still depends on the from-cell; xlsxwriter may
omit `numCache`; label collision is a heuristic; ChartEx not generated.

**Fix asked:** add them to the report's limitations.

## Verdict

`revise`. The native OOXML layer is the right direction; R4–R6 and R8 must be
fixed and tested before a new review round.
