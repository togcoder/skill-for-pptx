# T039 [docx] — Argon review, 2026-11-01

**Reviewer:** Gemini 4 Argon (via `ask_argon`), different model family from the
author (OpenCode/DeepSeek).
**Scope:** T039 REPORT, `domains/docx/DOMAIN.md`, `word_field_kit.py`,
`document_forge.py`, `document_audit.py` (attached files). Argon did **not** run
the repository or the tests; the review is a code/report critique, not a
reproduction. That limitation is recorded here.

**Verdict: `revise`** — fix R1–R3 before acceptance.

## Findings

### R1 — blocking — list of figures/tables and captions are partly frozen
`_add_field_list` used `REF` + `PAGEREF` for the number/page but appended the
caption text as a static run; `caption_bookmark` ended after the `SEQ` number,
not around the full caption. A new figure or an edited caption would not update
the list. The root cause of the repeated “Hình 1” was that Word's
`TablesOfFigures` collection was never updated (only `TablesOfContents`).

**Fix asked:** use `TOC \h \z \c "Figure"` / `"Table"` and update
`doc.TablesOfFigures`; if keeping `REF`, separate `fig-1-label` from
`fig-1-full`.

### R2 — major — audit misses broken bookmark pairs and uses one section width
`audit_docx` collected `bookmarkStart` names but never checked matching
`bookmarkEnd` IDs. `text_width_twips` was overwritten by the last section, so a
landscape/portrait mix produced false positives/negatives.

**Fix asked:** check `bookmarkStart`/`bookmarkEnd` balance per part; map each
table/image to the section that contains it.

### R3 — major — hard-coded `vi-VN` and `NUMPAGES` with restarted body pages
`_set_style_font` hard-coded `vi-VN` regardless of `meta.language`. The body
footer used `NUMPAGES` (total physical pages) while the body restarted at 1, so
the last page showed “Trang 7 / 12” instead of “7 / 7”.

**Fix asked:** pass the spec language through; use `SECTIONPAGES` (or a
`PAGEREF` to the end bookmark for multi-section bodies).

### R7 — minor — rung 4–5 is a manual COM run, not an automated check
The report named rung 4–5, but the `--render` path uses WordCraft/GridCraft and
the Word PDF was exported by a separate COM command. The name “full control”
overstates the supported chart/field surface.

**Fix asked:** integrate the native export into the render path, or state
clearly that rung 4–5 was a manual exact-file run.

### R8 — minor — overlap with the bridge modules
The docx side already imports `wordcraft_bridge`; no hard-coded path was found.
The architecture question (canonical builder vs bridge adapter) remains open.

**Fix asked:** define the boundary in `DOMAIN.md`; keep the bridge as an adapter.

### R9 — minor — limitations incomplete
Missing: appendix static prefix + `SEQ \r 1`, `w:tblCaption` metadata is not a
field, no merged cells/per-cell formatting, `SECTIONPAGES` with multiple body
sections, and the TOF update requirement.

**Fix asked:** add them to the report's limitations.

## Verdict

`revise`. The field model is the right direction; R1–R3 must be fixed and the
tests extended before a new review round.
