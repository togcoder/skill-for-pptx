# T039 [docx] — DocumentCraft: professional Word canon and real fields

## Frame

- **Question:** can a small, sourced document canon plus a field-first DOCX
  builder produce a professional report whose TOC, figure/table numbers,
  cross-references, running headers and appendices are *real Word links* — and
  whose layout survives a native Word refresh — without requiring WordCraft?
- **Hypothesis:** yes, if the builder writes `TOC`/`SEQ`/`REF`/`PAGEREF`/
  `STYLEREF` fields, links heading numbering to styles, uses fixed table grids
  and inline images, and an audit checks bookmark/field/geometry invariants.
  Falsifiers: a field that cannot resolve in Word; a TOC whose page numbers do
  not match the body; a table/image that leaves the text column; an appendix
  caption that cannot be numbered A.1; a build that requires WordCraft to exist.
- **Domain lens:** Word's native model (ECMA-376/ISO 29500 WordprocessingML,
  Word object model, built-in styles, fields, sections, tables, drawings),
  ISO 7144/2145/690/7200/8601/80000, WCAG 2.2 and PDF/UA/PDF/A as constraints.
- **Transfers from other domains:** none. The T034 “design tokens + critic”
  pattern is reused as a *method* (one data file read by generator and checker),
  not as PowerPoint values. No slide grid, motion token or click rhythm is
  imported. The transfer is tested by using Word's own page/field model, not a
  slide layout.

## Negative results and limitations

1. **WordCraft TOC page numbers were physical, not section-relative.** On the
   same DOCX, WordCraft updated the TOC to 4, 5, … while Word showed 1, 2, ….
   The final file uses Word for field refresh. WordCraft is a fallback with a
   documented limitation, not equivalent evidence.
2. **`TOC \c "Figure"` repeated the first SEQ number.** Word's caption list
   showed “Hình 1” for both figures after three update passes. Replaced the list
   with `REF` + `PAGEREF` per entry; numbers and pages are now correct and still
   live fields. `TOC \c` remains documented as an alternative.
3. **WordCraft `convert --update-fields` dropped `wp:docPr@descr`.** Alt text
   survived in `@title`, not `@descr`. Added a repair step for the WordCraft
   path; Word preserves `@descr` natively.
4. **WordCraft's PDF renderer clipped Vietnamese diacritics** (“Thực tế” →
   “Thc t”). The document evidence uses Word's PDF; WordCraft is only a
   fallback renderer.
5. **`SEQ … \s 1` did not produce A.1** for a directly numbered appendix heading.
   Replaced with an explicit `A.` prefix plus `SEQ … \r 1` per appendix;
   verified `Bảng A.1`.
6. **TOC Heading inherited Heading 1 numbering**, so body headings started at 3
   and front matter appeared in the TOC. Fixed by basing TOC Heading on Normal,
   removing `numPr`, and using an unnumbered Front Matter Heading for the
   abstract.
7. **No PDF/UA or PDF/A validation.** The DOCX has headings, alt text, table
   headers, language and title, but that is necessary, not sufficient. A veraPDF
   and tag-tree check are next.
8. **No LibreOffice rung 3.** Not installed on this host. Word rung 4–5 is
   stronger for Word fidelity but not independent.
9. **No human edit/print (rung 6).** The pages were inspected as renders; a
   person has not edited the DOCX in Word and printed it.
10. **Standards status is time-bound.** ISO 5966 is withdrawn; ISO 7144/2145/7200/
    690 were checked 2026-11-01. The full texts are paywalled; the report cites
    the catalogue/abstract pages.
